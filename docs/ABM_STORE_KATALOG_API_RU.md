**Кому:** команде разработки сайта ABM Store

**Дата:** 21.09.2026
**Версия:** 4
**Статус:** реализовано и развёрнуто. Учтены ваши уточнения от 21.09

Реализованы **все поля** из вашего документа — карточка, б/у, характеристики
и фотографии. Код на стороне базы развёрнут, методы активны. Осталось

- **Добавлено `quantity_total`** — общий остаток по всем витринам

  контейнерами и товар в них не кладётся (база это запрещает)

Остальные поля и формат ответов не менялись.

## 1. Общее

| | |
|---|---|
| Базовый адрес | сообщим вместе с тестовым токеном |
| Протокол | HTTPS, метод GET |
| Кодировка | UTF-8 |
| Авторизация | `Authorization: Bearer <токен>` — постоянный, только на чтение |
| Суммы | целое число сумов, без копеек |
| Даты | ISO-8601 со смещением: `2026-09-19T11:42:00+05:00` |

Токен отдаём один раз по защищённому каналу. У нас он хранится только в виде
хеша — восстановить его нельзя, при утере выпускаем новый и гасим старый.
Отзыв мгновенный, перезапуск приложения не нужен.

Токен выдаётся с областью `catalog`: он открывает только `/api/catalog/*`.
Отчётные методы учётной системы этим токеном недоступны — это ограничение на
нашей стороне, не настройка.

## 2. Каталог

```
GET /api/catalog/products?page=1&per_page=200
```

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `page` | целое | 1 | Номер страницы, с 1 |
| `per_page` | целое | 200 | Размер страницы, максимум 500 |
| `updated_since` | строка | — | ISO-8601. Отдаём только изменённое после этого момента |

Отдаём **полный список актуальных позиций** — вариант А из вашего раздела 3.
В выдачу попадают только товары, лежащие на складе, с остатком больше нуля
и заполненной розничной ценой. Чего в списке нет — того нет в продаже.

### Ответ

```json
{
  "total": 793,
  "page": 1,
  "per_page": 200,
  "items": [
    {
      "id": "iphone-17-pro-max~256~x~silver",
      "model_code": "iphone-17-pro-max",
      "model_name": "iPhone 17 Pro Max",
      "model_name_uz": "iPhone 17 Pro Max",
      "category": "iphone",
      "brand": "apple",
      "condition": "new",
      "price": 19500000,
      "old_price": null,
      "quantity": { "mirobod": 2, "sebzor": 0 },
      "quantity_total": 2,
      "sku": "IP17PM-256-SL",
      "storage_gb": 256,
      "color": { "code": "silver", "name_ru": "Серебристый", "name_uz": "Kumushrang" },
      "warranty_months": 12,
      "images": [
        { "url": "https://erp.abmstore.uz/api/app/get-file?file=ipt_iphone-17-pro-max_412_20260919143012.jpg",
          "color": "silver", "is_primary": true }
      ],
      "attributes": {},
      "is_active": true,
      "updated_at": "2026-09-19T11:42:00+05:00"
    }
  ]
}
```

`quantity` всегда содержит все витрины, даже с нулём — чтобы форма объекта
не менялась от позиции к позиции. Коды витрин подтвердим на созвоне.

### Про `updated_since`

Мы отдаём позиции, у которых `updated_at` больше переданного момента.
У позиции, которую ни разу не редактировали после заведения, `updated_at`
равен дате создания — такие тоже приходят. То есть первый полный обход
можно сделать с пустым `updated_since`, дальше — дельтами.

## 4. Поля

Все поля реализованы в API. Столбец «наполнение» — про данные, а не про код:
пока поле не заполнено, оно просто не приходит в ответе.

| Поле | Тип | Наполнение | Описание |
|---|---|---|---|
| `id` | строка | есть | Идентификатор карточки. Правила ниже |
| `model_code` | строка | заполняем | Только строчная латиница, цифры и дефис |
| `model_name` | строка | заполняем | Очищенное название. Служебных заметок в нём нет |
| `category` | строка | заполняем | Код из вашего справочника |
| `brand` | строка | заполняем | `apple`, `samsung`, `xiaomi`, `dyson`… |
| `condition` | строка | заполняем | `new` или `used` |
| `price` | целое | заполняем | Розничная цена в сумах |
| `quantity` | объект | есть | Остаток по витринам. См. вопрос 1 в разделе 8 |
| `quantity_total` | целое | есть | Общий остаток по всем витринам |
| `is_active` | булево | есть | Всегда `true`: отдаём только активные позиции |
| `updated_at` | строка | есть | Для `updated_since` |
| `old_price` | целое | заполняем | Приходит только если больше текущей цены |
| `storage_gb`, `ram_gb` | целое | заполняем | Память и ОЗУ |
| `color` | объект | заполняем | `{code, name_ru, name_uz}` |
| `sku` | строка | заполняем | Артикул |
| `warranty_months` | целое | заполняем | Нет — считайте 12 |
| `model_name_uz` | строка | заполняем | Название на узбекском |
| `description_ru` / `_uz` | строка | заполняем | Описание карточки |
| `images` | массив | заполняем | Фотографии. См. раздел 5 |
| `attributes` | объект | заполняем | Включая `acc_compat` |

### Как устроен `id`

| Вид | Формат | Пример |
|---|---|---|
| Новый (`condition: "new"`) | `model_code`~`storage_gb`~`ram_gb`~`color_code` | `iphone-17-pro-max~256~x~silver` |
| Б/у (`condition: "used"`) | идентификатор складской строки | `104721` |

Новые позиции одной конфигурации склеены в одну карточку, её `quantity`
— это сумма по складским строкам. Б/у аппараты не склеиваются: у каждого
свои IMEI и состояние батареи.

Разделитель `~`, потому что внутри `model_code` есть дефисы. Пустое поле
заменяется на `x` — иначе две разные конфигурации получили бы одинаковый
`id`.

> **Что важно знать.** `id` выводится из конфигурации. Если мы исправим
> опечатку в `model_code`, `storage_gb` или цвете — `id` изменится, и для
> вас это будет новая карточка. Поэтому сверку `model_code` на трёх
> позициях лучше сделать до массового заполнения.

Если у двух складских строк одной конфигурации разные розничные цены,
в каталог идёт **минимальная**.

### Поля б/у

Приходят только при `condition: "used"`. Для новой техники в ответе их нет
вовсе.

| Поле | Тип | Описание |
|---|---|---|
| `battery_health_pct` | целое | 1–100 |
| `imei` | строка | Последние 6 цифр, как вы и просили |
| `serial` | строка | Для Mac, iPad и часов |
| `sim_type` | строка | `single` · `dual` · `esim` · `sim_esim` |
| `market_code` | строка | `LL/A`, `KHA`, `RUA`, `LZA`, `JA` |
| `replaced_parts` | массив | `screen` · `glass` · `back_cover` · `body` · `battery` |
| `has_box`, `has_charger` | булево | Неизвестно — поле не приходит |

Незаполненные поля в ответе **отсутствуют**, а не приходят с `null`.
Появление поля не сломает разбор.

## 5. Фотографии

Храним у себя — от вас ничего не требуется. Фотографии загружаются на наш
сервер и отдаются по прямой ссылке, открытой без авторизации, как вы и
просили в разделе 5.3.

```json
"images": [
  { "url": "https://erp.abmstore.uz/api/app/get-file?file=ipt_iphone-17-pro-max_412_20260919143012.jpg",
    "color": "silver", "is_primary": true },
  { "url": "https://erp.abmstore.uz/api/app/get-file?file=ipt_iphone-17-pro-max_413_20260919143055.jpg",
    "color": "silver", "is_primary": false }
]
```

> **Важно для кэша.** Имя файла при каждой загрузке новое — «заменить
> фотографию по тому же адресу» у нас технически невозможно. Это ровно то
> поведение, которое вы просили: старая картинка не зависнет ни у вашего
> оптимизатора, ни в браузере покупателя.

Фотографии привязаны к **модели**, а не к конкретной позиции склада: все
позиции одной модели отдают один и тот же набор. Поле `color` привязывает
кадр к цвету — покупатель переключает цвет, фотография меняется. Не
привязано — общий кадр модели.

Ровно один кадр в наборе помечен `is_primary: true` — это кадр для плитки
в списке. Если фотографий у модели нет, приходит пустой массив.

## 6. Характеристики

Справочник из вашего раздела 7.4 заведён целиком. Тип значения задан для
каждой характеристики, поэтому числа приходят числами, а не строками, а
логические — булевыми.

```json
"attributes": {
  "acc_compat":   ["iphone-17-pro-max", "iphone-17-pro"],
  "acc_material": "silicone",
  "acc_feature":  "magsafe",
  "power_w":      20,
  "network_5g":   true
}
```

Характеристики, как и фотографии, заданы на уровне модели. Список
расширяемый — если нужна ещё одна, пришлите код и тип, заведём без изменения
схемы и без изменения формата ответа.

## 7. Ошибки

Тело ошибки одинаково для всех кодов:

```json
{ "error": { "code": 401, "message": "Invalid or missing API token" } }
```

| Код | Когда |
|---|---|
| `200` | Успех |
| `400` | Неверный параметр: `page` меньше 1, `per_page` больше 500, нераспознанный `updated_since` |
| `401` | Токен отсутствует, неизвестен, отозван или выдан на другую область |
| `500` | Сбой на нашей стороне. Подробности пишем в свой лог, наружу не отдаём |

Текст в `message` предназначен для разработчика, не для покупателя — на него
можно смотреть при отладке, но не показывать на витрине.

## 8. Что осталось открытым

Вопрос про `id` закрыт — сделали по вашему варианту, см. раздел 4.
Ниже то, что осталось.

### 1. Что означает `quantity`

Сейчас — учётная привязка товара к филиалу, а не физическое местонахождение.
Поле под фактическое местонахождение мы завели, но пока оно не заполнено,
и расхождения вида «Mirobodda» через API не видны.

> **Наше предложение.** Не запускать самовывоз в бою на этом варианте.
> Покупатель приедет за аппаратом в витрину, где его нет, — это хуже, чем
> отсутствие товара в каталоге. На тестовом контуре ограничение
> несущественно.

### 2. МХИК, единица измерения, ставка НДС

Этих полей в учётной системе нет — ни в карточке товара, ни рядом.
Фискальные чеки в шоурумах выбивает кассовое ПО, и эти значения до нас
не доходят.

Либо заводим поля у себя и проставляем их вручную для восьмисот позиций,
либо вы берёте их оттуда, где они уже ведутся. Ждём вашего ответа, где
МХИК ведётся сегодня.

## 9. Проверка после подключения

```bash
curl -H "Authorization: Bearer $TOKEN" \
     "https://<адрес>/api/catalog/products?page=1&per_page=5"
```

Ожидаем `200` и непустой `items`.

`total` — это число **карточек**, а не складских строк: новые позиции одной
конфигурации склеены. Оно будет заметно меньше восьмисот и будет расти по
мере заполнения — позиция без розничной цены на витрину не попадает.

Если `total` равен нулю — это не поломка доступа, а незаполненные данные.
Проверить доступ отдельно можно так: `401` вместо `200` означает проблему с
токеном, `200` с пустым списком — что наполнение ещё идёт.
